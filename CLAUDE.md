# status

Status page for mgrzmil.dev services. Cloudflare Worker: cron checks every 5 min, results in one KV key.

## Toolchain vs runtime

- Bun is the toolchain: `bun install`, `bun run <script>`, `bunx wrangler ...`, `bun test`.
- The Worker runs on Cloudflare workerd, NOT Bun. In `src/` (except tests) use only Web/Workers APIs
  (`fetch`, `Response`, `AbortSignal.timeout`, KV). No `Bun.*`, `bun:sqlite`, `node:fs`.
- Keep pure logic in `src/lib.ts` (no runtime APIs) so `bun test` covers it without mocks.

## Layout

- `src/index.ts` — check definitions, `scheduled()` runner, `GET /api/status`.
- `src/lib.ts` — status classification, state shape, ring buffers (288 recent samples, 90 days).
- `worker-configuration.d.ts` — generated by `bun run types`; rerun after changing `wrangler.toml`.

## Constraints

- KV free tier: 1000 writes/day. Exactly one `put` per cron run (288/day). Never write per component.
- Worker free tier: 10 ms CPU per invocation (fetch wait time does not count).

## Scripts

- `bun run dev` — local worker; trigger cron with `curl localhost:8787/__scheduled`.
- `bun test`, `bun run typecheck`
- `bun run deploy`, `bun run tail`, `bun run state` (dump remote KV state).
